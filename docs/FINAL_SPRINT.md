## Win condition

The entire entry should make one loop unmistakable in under three minutes:

> The page carries evidence provenance, the agent proposes one bounded experiment, the player visibly approves it, WebMCP exposes exact apply, a second trial tests the change, a visible check-in resolves what comparison may claim, and undo restores the prior state.

Every public artifact should reinforce that loop. Do not add unrelated features unless they materially improve one of the four equally weighted criteria: WebMCP leverage, execution, potential impact, or creativity and ambition.

The official process first applies a pass/fail viability and WebMCP-fit screen, then scores those four criteria equally. Ties are broken in listed order, making **WebMCP Leverage** the first tie-break. Protect eligibility first, lead every artifact with the capability-gating interaction, and use the same-player result to make the impact case credible rather than generic.

## Release commands

`npm run submission:status` prints all blockers without failing, so it is safe during the sprint. `npm run submission:check` exits nonzero until the machine-readable release record, public artifacts, signed-out checks, exact human evidence, cold review, claim reconciliation, and immutable Git tag are complete. Keep this gate separate from `npm run verify`: product verification should remain green while release evidence is still being gathered.

In `submission.release.json`, use lowercase `better`, `same`, `worse`, or `skipped`; copy the exact verdict token; enter the absolute baseline and adapted values under `baselineMetrics` and `adaptedMetrics`; use JSON `null` for an unavailable median collect time (target visible → collected). The compiler derives every public delta and verifies the verdict from those values. Commit the final record and generated `submission/ready` packet, create its declared Git tag at `HEAD`, push both, then run the strict check from a clean worktree.
